How the source is organised

Repository: github.com/R3CT01/PEK-TV. You may read the code; see the LICENCE file for what else you may do with it.

One branch

Everything lives on main: the backend, the Flutter UI, the Android host, plugins, skins, cloud workers, the build workflow and these docs. There is no separate branch per platform, so a change to shared code (backend/, flutter_ui/, plugins/, skins/ or cloud/) is made once.

PartFolderBuild guide
C++ backendbackend/The backend
Android app (Kotlin host, libmpv, Chaquopy, JNI)android/The Android app

Shared code stays in backend/ and flutter_ui/. A new platform gets its own runner folder (for example linux/ or windows/) and its own workflow file, next to android/ and build.yml. Android is the only one today.

How the parts fit

  Flutter UI (flutter_ui/)  <----HTTP, port 8080--->  C++ backend (backend/)
   |  plugin screens (Python screen.py) are drawn      |  scans folders and network shares
   |  natively by the app                              |  streams files, subtitles, trailers
   |  libmpv is driven over platform channels (pek/*)  |  runs plugin backends via embedded Python,
   |                                                   |  behind hesper_guard.py
   v                                                   v
  PEK Cloud + PEK Store (Cloudflare Workers + D1), optional

On Android the Kotlin host (MainActivity) starts the backend through JNI and runs plugin Python with Chaquopy. Video and music are played by libmpv (MpvController, MpvAudioController) and the Flutter UI controls them over the pek/* platform channels. The Flutter UI is the only front end; on other systems you can run the backend with dev.sh.

The server only answers the device it runs on unless you set PEK_BIND and PEK_TOKEN.

A note on old names

The project used to be called Hesper. Some internal names still say so on purpose, so existing installs keep working: saved settings keys (hesper_*), the hesper and hesper_host plugin names, HESPER_* environment variables, and hesper_guard.py. Do not rename them without a migration.
