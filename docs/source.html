How the source is organised

Repository: github.com/R3CT01/PEK-TV. You may read the code; see the LICENCE file for what else you may do with it.

Branches

BranchContainsBuild guide
mainThe C++ backend, the web UI (www/), plugins, skins, cloud workers and the docs. The reference for everything except the Android app.Main branch
androidEverything in main plus android/ (Kotlin app, libmpv, Chaquopy, JNI), .github/workflows/build.yml and tools/. A few files differ on purpose, for example www/app_storage.js (Android storage permission) and the docked mini player in www/player.js.Android branch

The two branches are copies that drift. When you change a shared file (anything in www/, backend/, plugins/, skins/ or cloud/), make the same change on both. To see what differs: check out one branch next to the other and run diff -rq.

Repository layout

backend/          C++ server + embedded Python (dev.sh builds it)
www/              the whole web UI, plain JavaScript, no build step
plugins/          bundled plugins: tmdb-discover, weather
plugin_packages/  plugin zips and sources prepared for distribution
skins/            bundled skins: default (PEK Ember), green, neon
cloud/            Cloudflare Workers: PEK Cloud (sync, accounts, subtitles) and the PEK Store
docs/             this site (GitHub Pages)
PLUGINS.md  SKINS.md  SUBTITLES.md  LOCAL_METADATA.md   reference docs

android branch only:
android/          Gradle project: Kotlin app, JNI, Python runner, resources
.github/workflows/build.yml   the APK build
tools/            sync_providers.js

How the parts fit

  Web UI (www/)  <----HTTP, port 8080--->  C++ backend (backend/)
   |  plugin UIs run in a sandboxed iframe        |  scans folders and network shares
   |                                              |  streams files, subtitles, trailers
   |                                              |  runs plugin backends via embedded Python,
   |                                              |  behind hesper_guard.py
   v                                              v
  PEK Cloud + PEK Store (Cloudflare Workers + D1), optional

On Android the same UI is shown inside the Kotlin app, which starts the backend through JNI, runs plugin Python with Chaquopy and plays video with libmpv. On other systems you run the backend and open the UI in a browser.

The server only answers the device it runs on unless you set PEK_BIND and PEK_TOKEN.

Backend modules (backend/)

FilesWhat they do
core.cpp, server.cppProgram entry, embedded Python, the HTTP server on port 8080, plugin / skin routes, remote-access token.
media_scanner.cpp, nfo.hLibrary scanner, NFO and artwork reading.
vfs.cpp, vfs_smb.cpp, vfs_nfs.cpp, vfs_ftp.cpp, vfs_http.cpp, discovery.cppOne virtual file system over local folders, SMB, NFS, FTP, WebDAV and UPnP / DLNA, plus network discovery.
playback.cpp, range_stream.hStreaming files with byte ranges, including files over 4 GB on 32-bit builds.
music.cpp, music_tags.cppThe music library and its /api/music/* routes (albums, artists, songs, search, cover art, audio streaming). Song tags and embedded covers are read straight from MP3, FLAC, Ogg / Opus and M4A files, so it works without ffprobe, on Android and over network shares. It refreshes after every normal scan; see MUSIC.md.
plugin_install.h, skin_install.h, github_install.hServer-side checks and installation for plugin zips, skin zips and GitHub releases.
hesper_guard.pyThe plugin guard: decides whether a plugin's Python backend may run and with what access. The file keeps its old name.
torrent.cpp, torrent_routes.cppOptional libtorrent engine and its /api/torrent/* routes.
subtitles.h, trailer.hSubtitle look-up through the cloud worker; trailer playback without the YouTube embed.

A note on old names

The project used to be called Hesper. Some internal names still say so on purpose, so existing installs keep working: saved settings keys (hesper_*), the hesper and hesper_host plugin names, HESPER_* environment variables, and hesper_guard.py. Do not rename them without a migration.
